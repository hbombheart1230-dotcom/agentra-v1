# Agentra P1.6 — 제품·연구 아이덴티티 및 아키텍처 방향 (통합본)

> 상태: **홍사장 대화 기반 방향 확정 / 구현·논문 신규성 미검증**
> 작성: 2026-11-03
> 적용 범위: P1.6 설계 입력. P1.5 RF, D00, C01~C06 실행 계약을 변경하지 않는다.
> 원칙: 중복 제안은 이 문서의 단일 정의로 통합하고, 확정 사실과 연구 가설을 구분한다.

## 1. 목적과 성공 기준

Agentra는 **한국 주식시장에 대응하는 지식·경험 기반의 글로벌 연계 적응형 투자 에이전트 시스템**을 지향한다.

제품 목표와 연구 목표는 **동등한 우선순위**다.
- 제품: 실사용 가능한 시장 분석·판단·위험통제·승인 기반 주문 실행, 비용 반영 위험조정 성과.
- 연구: 글로벌 선행정보, 시장 관계 지식, 판단/결과 경험 지식의 기여를 재현 가능한 실험으로 검증.
- 둘은 공통 데이터·실험 인프라를 공유하되, **실제 수익성과 학술적 신규성은 각각 별도 입증**한다.
- 논문 주제·신규성·성과 우위는 현재 **확정되지 않았다**.

## 2. 고정 아이덴티티: 7에이전트 유지

7개 역할은 폐기·통합하지 않는다. 새 인프라나 도구를 '8번째 에이전트'로 세지 않는다.

| 에이전트 | 책임 | P1.6 강화 방향 |
|---|---|---|
| Commander | 실행 주기·작업 흐름 지휘 | 도구/Skill 오케스트레이션 |
| Strategist | 투자 계획·가설·시나리오 | 글로벌 지표 기반 전략과 지식 검색 |
| Scanner | 데이터 수집·특징 계산·후보 랭킹 | 관계·패턴·과거 사례 활용 |
| Monitor | 시장 감시, OrderIntent 생성 | 시장 이벤트/조건 감시; 직접 주문 금지 |
| Supervisor | 정책·위험·승인/거절/수정 | 지식 신뢰도와 위험 검증 |
| Executor | 승인된 의도만 실행 계층에 전달 | 주문·체결·실패 통제 |
| Reporter | 이벤트·결과 보고·사후 분석 | 예측/거래 결과와 판단 근거 연결, 지식 갱신의 증거 제공 |

**불변 경계:** Monitor는 주문하지 않는다. Supervisor 승인 없이 실행하지 않는다. Guard는 승인보다 우선한다. 동일 intent_id 중복 실행 금지. 실거래 기본 차단. DTO/IO 계약 호환성과 run_id 추적을 유지한다. Reporter가 근거를 생성할 수 있으나 검증되지 않은 경험을 자동으로 '진실'로 승격시키지 않는다.

## 3. 핵심 차별화 가설: 데이터 → 지식 → 경험

### 3.1 시장 지식화
원시 가격·재무·공시·뉴스·거시 데이터에서 사건, 시간차, 종목·산업 관계, 시장 국면, 근거와 신뢰도, 유효기간을 구조화한다. 단순 저장·임베딩·RAG만으로 지식화 완료라 하지 않는다.

### 3.2 경험 지식화
매 판단에 입력 데이터의 **관측 가능 시점**, 사용한 가설/지식 버전, 에이전트별 의견·반론, 최종 결정, 승인/Guard 사유, 주문/관망 여부, 후속 실제 결과, 예측 오류 및 수정 이유를 연결한다.

### 3.3 지식 수명주기
**수집 → 정규화 → 가설/관계 생성 → 검증 → 지식 등록 → 판단에 활용 → 사후 평가 → 유지·감쇠·수정·폐기**. 성공 거래의 우연한 패턴을 강화하지 않도록 표본 수·통계적 불확실성·시장 국면 변화·정보 누출을 관리한다. 원본 데이터와 판단 당시의 지식 버전을 보존하여 재현성을 확보한다.

## 4. 글로벌 선행정보를 활용한 한국시장 대응

주요 연구 대상은 **미국 시장·반도체·가상자산·주요 지수·금리·환율·변동성**이 한국 주식시장에 미치는 조건부 영향이다.

| 글로벌 신호 후보 | 한국시장 분석 대상 | 검증 질문 |
|---|---|---|
| SOX, NVIDIA, Micron | 삼성전자·SK하이닉스·반도체 공급망 | 미국 반도체 정보가 국내 개장/장중 반응을 설명하는가 |
| NASDAQ, S&P 500 | KOSPI·KOSDAQ·성장주 | 위험 선호의 정보 전달이 유효한가 |
| BTC, ETH | 고변동성·위험자산 | 추가 예측력이 실제 존재하는가 |
| 미 국채금리, 달러/원 | 외국인 수급·대형주 | 금융환경 변화가 관계를 조절하는가 |
| VIX 등 | 국내 변동성·방어 전략 | 위험 회피 국면에서 효과가 달라지는가 |

이 표는 **검증 전 가설**이다. 단순 상관관계를 인과관계나 항상 유효한 선행성으로 간주하지 않는다. 미국 장 마감/한국 개장, 휴장·서머타임·공시 시각·수정 데이터 등 **시점 정합성**을 우선한다.

## 5. Build보다 Integrate: 기존 자산과 외부 생태계 재사용

### 5.1 내부 자산
- `docs/`: 아키텍처, 정책, 작업 절차, 실패/수정 사례. **모든 문서가 Skill은 아니다.**
- 기존 `composite_skills`, `skill_map`, `registry` 등 초기 Skill 설계: 최신 코드·계약과 대조하여 재사용 가능 부분 식별.
- 키움 REST API 카탈로그·Discovery·Planning·Request 계층: MCP와 **유사한 추상화**를 보유하지만 **표준 MCP 서버 구현 여부는 별도 확인**.
- 기존 7에이전트와 승인·Guard·DTO 경계: 유지.

### 5.2 자산 분류 — 중복 정의 금지
- **Policy/Contract**: 항상 적용되는 불변 규칙; Skill로 바꾸어 임의 우회 불가.
- **Skill**: 호출 조건, 입력, 절차, 출력, 실패/검증 기준이 명확한 재사용 작업 능력.
- **Knowledge**: 출처·시점·신뢰도·버전을 가진 검색/추론 대상.
- **Runbook**: 운영·장애·복구 절차.
- **MCP Tool/Adapter**: 외부 기능/데이터를 표준 인터페이스로 제공하는 연결 계층.

문서를 단순 복사해 Skill이라고 부르지 않는다. 개발 에이전트용 Skills와 투자 런타임용 Skills는 권한·배포·보안 경계를 분리한다.

### 5.3 도입 원칙
기존에 잘 작동하는 데이터 수집·분석·백테스트·저장 기술은 검토 후 가져온다. **교체 가능한 어댑터 → 표준 DTO → 기존 에이전트** 순으로 연결한다. 외부 MCP/Skills는 기본 읽기 전용이며 주문 권한을 직접 갖지 않는다. 실거래는 기존 Supervisor/Guard/Executor 경로만 허용한다.

도입 전 확인: 라이선스, 유지보수, 데이터 품질/지연, 한국시장 적합성, 비용, 재현성, 보안, 벤치마크. TradingAgents·FinRobot·Qlib·기타 금융 Skills는 **참고/비교 후보**이지 현재 채택 확정 목록이 아니다.

## 6. P1.6 개념 구조

```text
Global/KR Markets + Events + Broker APIs + External MCP/Skills
                         |
              Adapters / Provenance / DTO
                         |
            Knowledge & Experience Layer
       (evidence, relations, versions, outcomes)
                         |
Commander -> Strategist -> Scanner -> Monitor -> OrderIntent
    |                                         |
    +----------------> Supervisor <-----------+
                           |
                     Agent Executor
                           |
                    Execution Guards
                           |
                       Broker API
                           |
                  Event Log / Reporter
                           |
                Evaluation / Knowledge Update
```

Knowledge Layer는 **공유 인프라**이며 별도 에이전트가 아니다. 위 도식은 개념도이며 실제 런타임 순서와 데이터 접근 권한은 기존 계약을 기준으로 상세 설계한다.

## 7. 논문·제품 공통 실험 설계 (제안, 미확정)

- 비교군: 국내 데이터만 사용, 글로벌 지표 추가, 관계 지식 추가, 경험 지식 갱신 추가. TradingAgents 등 외부 기준선은 동일 데이터·시점·비용 조건에서 비교 가능할 때만 채택.
- 검증: 워크포워드/시계열 외부 검증, 거래비용·슬리피지, 시장 국면별 분해, 통계적 불확실성, ablation.
- 지표: 방향성/확률 보정, 위험조정 수익률, 최대낙폭, 회전율, 거래 실패·Guard 차단, 지식 갱신 후 성능 변화.
- 누출 방지: 실제 이용 가능 시점의 데이터만 사용하고 수정 공시·사후 결과가 과거 의사결정에 섞이지 않게 한다.
- 연구 질문: **시장 국면별로 달라지는 글로벌-한국시장 관계와 과거 판단 경험을 지식화했을 때, 고정 전략 및 지식 미사용 에이전트보다 유의미한 개선이 있는가?**
- 연구 기여는 선행연구 조사 및 실험 결과 이후 확정한다.

## 8. 단계별 우선순위와 범위 경계

1. **P1.5:** 기존 계약·RF 품질 게이트 충족 후 신속 종결. P1.6 기능을 P1.5에 끼워 넣지 않는다.
2. **P1.6 설계:** 현재 `docs/`·Skill·키움 API 인벤토리, 7에이전트 책임/DTO 검토, 지식·경험 스키마, 어댑터 경계, 연구 질문과 최소 실험 계획을 확정.
3. **P1.6 구현:** 소규모 end-to-end 수직 절편으로 수집→지식화→판단→검증을 증명하고 외부 도구를 선별 통합.
4. **이후 연구/운용:** 충분한 검증을 거쳐 비교 실험과 실전 적용 범위를 확대. P1.7로 기계적으로 미루지 않고 P1.6에서 실험 가능한 기반을 마련한다.

## 9. 미결정 사항 (확정으로 오인 금지)

- 저장소 엔진(시계열 DB, 관계형 DB, 그래프 DB, 벡터 검색), SSD 용량/배치 및 데이터 보존 기간
- 채택할 MCP·Skills·백테스트 엔진 및 라이선스
- 지식 신뢰도 계산법·관계 갱신/폐기 기준·시장 국면 모델
- 실험 종목군, 기간, 빈도, 비용 모델, 연구 기여 주장
- 현행 `docs/`의 정확한 Skill 전환 대상과 키움 MCP 프로토콜 구현 수준

## 10. 이번 대화의 중복·변경사항 통합 기록

- **'7에이전트 변경/확장' → '7에이전트 고정 + 능력 확장'**으로 확정.
- **'Knowledge Agent 추가' → '공유 Knowledge & Experience Layer'**로 통일.
- **'모든 docs를 Skill로 전환' → 'Policy / Skill / Knowledge / Runbook 분류 후 선별 전환'**으로 정정.
- **'키움은 MCP다' → 'MCP 유사 구조, 표준 호환은 확인 필요'**로 명확화.
- **'외부 도구를 전부 직접 개발' → '검증된 도구 재사용, 핵심 지식/판단/안전 계약은 Agentra 소유'**로 확정.
- **'한국시장 특화만으로 논문 차별화' → '조건부 선행관계 + 검증 가능한 경험 지식화의 기여를 실험'**으로 구체화.
- **'P1.7부터 실험' → 'P1.6에서 실험 가능 기반 구축, 이후 검증 확대'**로 조정.
- **'SSD 구매 = 지식화 완성' → '저장 용량은 기반일 뿐, 출처·시점·버전·검증 체계가 핵심'**으로 정리.

---
**관리 원칙:** 이 문서는 P1.6 방향의 단일 통합 초안이다. P1.5의 실행 지시·안전 계약보다 우선하지 않으며, 설계 확정 전에는 구현 완료를 주장하지 않는다.
