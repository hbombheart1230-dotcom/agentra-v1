# C03 — RF 상세 계획 실행 배정

## 최우선 작업 기준
홍사장 지시: 담당별 진행 중 RF를 유지하고 상세 계획의 남은 항목을 끝까지 처리한다. 매회 DONE 쉬운 RF를 다시 찾거나 단일 HOLD 때문에 RF를 바꾸지 않는다. 기존 DONE-FIRST의 배정 해석보다 이 원칙이 우선한다.
범위·순서·완료 조건은 정본 `docs/refactor/plan/rf_details/RF-XXX_IMPLEMENTATION.md`와 해당 RF 원본 체크리스트를 따른다. 이슈는 완료 증거일 뿐 계획을 대체하지 않는다.
막힌 항목은 원인·해소 담당을 기록하고 같은 RF의 독립 항목을 계속한다. 전체 잔여 항목이 실제 차단된 경우에만 C03이 근거·복귀 조건을 남겨 다음 RF를 배정한다. 개발을 완료해 C04/C05로 인계한 경우 개발자는 다음 RF를 진행할 수 있다.
D00 Owner·안전·frozen 계약과 실제 G1/G2/G3 요건은 유지한다. 완료 작업 재실행 금지.

## 실행
1. C01/C02의 진행 RF를 먼저 확인하고 해당 RF 상세 문서의 잔여 항목을 확인한다. 그 뒤 코드·원격 SHA·이슈 증거로 완료/진행/미완료를 구분한다.
2. A/B 진행 주문은 보존한다. 빈 슬롯은 같은 진행 RF 상세의 다음 안전 미완료 항목으로 채운다. C01/C02에 ACTIVE_RF와 NEXT_ITEM을 유지한다. 단일 HOLD·새 커밋 없음·NO_READY_ORDER로 종료하지 않는다.
3. 각 주문에 RF_DETAIL 경로·절/항목, ORDER_ID·ITEM, FIRST_UNMET, 허용 경로, SOURCE/TARGET blob, 테스트·완료 조건을 명시한다. 상세 계획에 없는 작업을 임의 공급하지 않는다. 계획 내 실제 결함 수정은 해당 항목과 연결한다.
4. C01/C02를 원격 발행·재조회한다. G3만 남으면 C04, 전체 게이트 충족이면 C05에 exact SHA로 인계한다. A/B 파일 중복 배정·완료 작업 재발행 금지.
5. A/B 각각 READY·IN_PROGRESS·BLOCKED와 증거를 #36에 간결히 보고한다. BLOCKED는 조사한 후보별 경로·차단 규칙·해소 담당을 명시한다. 미조사 후보를 전부 차단으로 간주하지 않는다.

D00와 agentra-contract-guard를 준수한다. 현재 주문·미완료만 본문 교체한다. 과거 이력·중복 지침을 덧붙이지 않는다.
