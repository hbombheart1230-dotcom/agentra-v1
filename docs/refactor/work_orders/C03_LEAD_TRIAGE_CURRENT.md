# C03 — 작업 배정

매시 00분 정본 integration/p1.5의 D00와 이 파일을 읽는다. 입력은 #11/#12/#32/#36 신규 증거와 현재 RF 큐다. 스킬은 agentra-contract-guard다.

## 실행
1. A/B 원격과 C01/C02를 대조해 각 주문을 미완료·진행 중·원격 완료로 구분한다. 완료 항목은 제거하고 진행 중 유효 항목은 보존한다.
2. A 또는 B의 실행 가능한 주문이 없으면 신규 커밋 유무와 관계없이 해당 담당자의 미완료 RF를 조사한다. FIRST_UNMET, 실제 source/consumer/test, Owner, 재현 또는 누락 증거를 확인한다. 앞선 HOLD와 같은 이유만 반복하지 말고 독립 후보로 이동한다.
3. 안전한 수정·실패 재현·누락 소비 경로 검증을 구체 주문으로 만든다. ORDER_ID, ITEM, RF, FIRST_UNMET, 허용 경로, SOURCE/TARGET blob, 테스트, 완료 조건을 명시한다. A/B 교차 파일 중복 배정은 금지한다.
4. C01/C02를 원격 갱신하고 새 blob을 재조회한다. G3만 남은 항목은 C04, 전체 게이트 충족 항목은 C05에 exact SHA와 증거를 인계한다. 하나를 발행한 뒤에도 다른 담당자의 빈 주문과 독립 안전 항목을 처리한다.
5. #36에 A/B READY·IN_PROGRESS 수, 새 ORDER_ID와 작업서 blob, 조사한 후보별 판정, 다음 담당을 기록한다.

## 종료 조건
A/B 각각 아래 중 하나를 증명해야 종료한다.
- READY: 실행 가능한 구체 주문을 원격 발행하고 재조회했다.
- IN_PROGRESS: 진행 중 주문이 여전히 유효하며 원격 증거로 중복 배정을 피했다.
- BLOCKED: 담당자의 남은 후보를 조사한 범위와 후보별 경로·Owner·차단 규칙·해소 담당을 제출했다. 기술 접근 실패면 정확한 명령·오류와 미조사 범위를 보고한다.

새 커밋 없음, NO_DELTA, NO_READY_ORDER, 한 RF의 HOLD만으로 종료할 수 없다. 전수 확인하지 않은 후보를 전부 차단됐다고 간주하지 않는다. 작업이 없다는 보고를 신규 작업 설계의 입력으로 사용한다.
