# C03 — RF 상세 계획 실행 배정

## 최우선 작업 기준
작업 범위·순서·완료 조건은 정본 `docs/refactor/plan/rf_details/RF-XXX_IMPLEMENTATION.md`와 해당 RF 원본 체크리스트를 따른다. C 작업서는 이를 실행하는 주문이며, 이슈·댓글·과거 보고로 계획을 대체하거나 범위를 늘리지 않는다. 이슈는 SHA·테스트·완료 증거 확인용이다. 현재 코드와 증거로 완료 항목을 제외하고 남은 항목을 순서대로 처리한다. D00의 Owner·안전·frozen 계약은 유지한다. 충돌은 해당 항목만 근거와 함께 C03에 넘기고 독립 항목은 계속한다.

## 실행
1. RF 상세 문서와 물리 큐에서 미완료 항목을 확인한다. 그 뒤 코드·원격 SHA·이슈 증거로 완료/진행/미완료를 구분한다.
2. A/B 진행 주문은 보존한다. 빈 슬롯은 RF 상세의 다음 안전 미완료 항목으로 채운다. 단일 HOLD·새 커밋 없음·NO_READY_ORDER로 종료하지 않는다.
3. 각 주문에 RF_DETAIL 경로·절/항목, ORDER_ID·ITEM, FIRST_UNMET, 허용 경로, SOURCE/TARGET blob, 테스트·완료 조건을 명시한다. 상세 계획에 없는 작업을 임의 공급하지 않는다. 계획 내 실제 결함 수정은 해당 항목과 연결한다.
4. C01/C02를 원격 발행·재조회한다. G3만 남으면 C04, 전체 게이트 충족이면 C05에 exact SHA로 인계한다. A/B 파일 중복 배정·완료 작업 재발행 금지.
5. A/B 각각 READY·IN_PROGRESS·BLOCKED와 증거를 #36에 간결히 보고한다. BLOCKED는 조사한 후보별 경로·차단 규칙·해소 담당을 명시한다. 미조사 후보를 전부 차단으로 간주하지 않는다.

D00와 agentra-contract-guard를 준수한다. 현재 주문·미완료만 본문 교체한다. 과거 이력·중복 지침을 덧붙이지 않는다.
